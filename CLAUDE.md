## Logging

### ✅ DO: Use the Centralized Logger

**Always use the logger service instead of console.***

```typescript
// ✅ CORRECT
import { logger } from '@/services/logger';

logger.debug('MealPlanning', 'Fetching meal plans', { filters });
logger.info('Travel', 'User logged in successfully');
logger.warn('Finance', 'Rate limit approaching', { remaining: 10 });
logger.error('API', 'Failed to fetch data', error);
```

```typescript
// ❌ INCORRECT
console.log('Fetching meal plans', filters);
console.error('Failed to fetch data', error);
console.warn('Rate limit approaching');
```

### Logger Methods

- **`logger.debug(domain, message, context?)`** - Development-only logs for debugging
- **`logger.info(domain, message, context?)`** - Informational messages (dev only)
- **`logger.warn(domain, message, context?)`** - Warnings (dev + production)
- **`logger.error(domain, error, context?)`** - Errors (dev + production)
- **`logger.api(method, url, data?)`** - API request logging
- **`logger.apiResponse(method, url, status, data?)`** - API response logging

### Domain Names

Use consistent, descriptive domain names:
- **API Layer**: `'MealPlanning'`, `'Finance'`, `'Travel'`, `'Shopping'`
- **Services**: `'Service'`, `'Briefing'`, `'Nutrition'`
- **UI Components**: `'UI'`, `'Modal'`, `'Form'`
- **Hooks**: `'Hooks'`
- **Data Layer**: `'DataEvents'`, `'ReactQuery'`

### Context Objects

Always provide context for better debugging:

```typescript
// ✅ CORRECT
logger.error('API', 'Failed to update task', {
  taskId,
  userId,
  error: error.message,
  statusCode: error.statusCode
});
```

```typescript
// ❌ INCORRECT
logger.error('API', `Failed to update task ${taskId}`);
```

### Exceptions

Console usage is **only allowed** in:
- Test files (`*.test.ts`, `*.spec.ts`, `src/test/setup.ts`)
- Scripts (`src/scripts/**`)
- The logger service itself (`src/services/logger.ts`)

## Error Handling

### ✅ DO: Use Typed Error Classes

**Always use custom error classes from `@/lib/errors` instead of generic `Error`**

```typescript
// ✅ CORRECT
import { AuthenticationError, NotFoundError, AuthorizationError } from '@/lib/errors';

if (!user) {
  throw new AuthenticationError('Not authenticated');
}

if (!task) {
  throw new NotFoundError('Task', taskId);
}

if (!hasPermission) {
  throw new AuthorizationError('Access denied to shared resource');
}
```

```typescript
// ❌ INCORRECT
throw new Error('Not authenticated');
throw new Error('Task not found');
throw new Error('Access denied');
```

### Available Error Classes

| Error Class | Use Case | Example |
|-------------|----------|---------|
| `AuthenticationError` | User not logged in, invalid token | `throw new AuthenticationError('Not authenticated')` |
| `AuthorizationError` | Insufficient permissions, RLS violations | `throw new AuthorizationError('Access denied to project')` |
| `NotFoundError` | Resource doesn't exist | `throw new NotFoundError('Task', taskId)` |
| `ValidationError` | Invalid input data | `throw new ValidationError('Invalid email format')` |
| `NetworkError` | Connection issues | `throw new NetworkError('Failed to connect')` |
| `DatabaseError` | Database operation failures | `throw new DatabaseError('Query failed')` |
| `ServerError` | 5xx server errors | `throw new ServerError('Internal server error', 500)` |
| `ConflictError` | Duplicate entries, conflicts | `throw new ConflictError('Task already exists')` |
| `RateLimitError` | Too many requests | `throw new RateLimitError('Rate limit exceeded', 60)` |

### Error Handling in Try-Catch

```typescript
// ✅ CORRECT - Parse errors and use typed classes
import { parseToLifeSyncError } from '@/lib/errors';

try {
  await supabase.from('tasks').insert(task);
} catch (error) {
  const lifeSyncError = parseToLifeSyncError(error);
  logger.error('Tasks', lifeSyncError, {
    code: lifeSyncError.code,
    statusCode: lifeSyncError.statusCode,
  });
  throw lifeSyncError; // Re-throw the typed error
}
```

### React Query Error Handling

```typescript
// ✅ CORRECT - Use error helpers
import { getUserErrorMessage, isRetryableError } from '@/lib/errors';

const { error } = useQuery({
  queryKey: ['tasks'],
  queryFn: fetchTasks,
});

if (error) {
  const message = getUserErrorMessage(error); // User-friendly message
  return <ErrorState error={error} onRetry={isRetryableError(error) ? refetch : undefined} />;
}
```

## Accessibility

### ✅ DO: Add ARIA Labels to Interactive Elements

**All icon-only buttons and interactive elements must have `aria-label`**

```typescript
// ✅ CORRECT
<button onClick={handleClose} aria-label="Close">
  <X className="w-4 h-4" />
</button>

<button onClick={handleEdit} aria-label="Edit task">
  <Edit className="w-4 h-4" />
</button>

<button onClick={handleDelete} aria-label="Delete item">
  <Trash className="w-4 h-4" />
</button>
```

```typescript
// ❌ INCORRECT - Missing aria-label
<button onClick={handleClose}>
  <X className="w-4 h-4" />
</button>
```

### Dynamic ARIA Labels

Use state-dependent labels for better context:

```typescript
// ✅ CORRECT
<button
  onClick={toggleRecording}
  aria-label={isRecording ? "Stop voice recording" : "Start voice recording"}
>
  <Mic className="w-4 h-4" />
</button>

<button
  onClick={toggleFilters}
  aria-label={showFilters ? "Hide filters" : "Show filters"}
>
  <Filter className="w-4 h-4" />
```

### Keyboard Navigation

**All modals must support Escape key to close**

```typescript
// ✅ CORRECT - Modal with keyboard support
useEffect(() => {
  const handleKeyDown = (event: KeyboardEvent) => {
    if (event.key === 'Escape') {
      onClose();
    }
  };

  if (isOpen) {
    window.addEventListener('keydown', handleKeyDown);
    return () => window.removeEventListener('keydown', handleKeyDown);
  }
}, [isOpen, onClose]);
```

### Form Accessibility

## TypeScript Patterns

### ✅ DO: Use Type Guards Instead of Type Assertions

```typescript
// ✅ CORRECT
import { isTask, isShoppingItem } from '@/types/guards';

if (isTask(data)) {
  console.log(data.title); // TypeScript knows data is Task
}
```

```typescript
// ❌ INCORRECT
const task = data as Task; // Unsafe!
console.log(task.title);
```

### Type Safety for Unknown Data

```typescript
// ✅ CORRECT
import { parseToLifeSyncError, isObject, isString } from '@/lib/errors';

function processApiResponse(response: unknown) {
  if (!isObject(response)) {
    throw new ValidationError('Invalid response format');
  }

  if ('error' in response && isString(response.error)) {
    throw parseToLifeSyncError(response.error);
  }

  // Safe to use response here
}
```

### Avoid `any`

```typescript
// ✅ CORRECT
function formatDate(date: Date | string): string {
  const d = typeof date === 'string' ? new Date(date) : date;
  return d.toISOString();
}
```

```typescript
// ❌ INCORRECT
function formatDate(date: any): string {
  return new Date(date).toISOString();
}
```

## React Patterns

### Component Structure

```typescript
// ✅ CORRECT - Well-structured component
import React, { useState, useEffect } from 'react';
import { logger } from '@/services/logger';
import { NotFoundError } from '@/lib/errors';

interface TaskCardProps {
  taskId: string;
  onComplete: (id: string) => void;
}

export const TaskCard: React.FC<TaskCardProps> = ({ taskId, onComplete }) => {
  const [task, setTask] = useState<Task | null>(null);
  const [isLoading, setIsLoading] = useState(true);

  useEffect(() => {
    fetchTask();
  }, [taskId]);

  const fetchTask = async () => {
    try {
      const data = await getTask(taskId);
      setTask(data);
    } catch (error) {
      logger.error('UI', 'Failed to fetch task', { taskId, error });
    } finally {
      setIsLoading(false);
    }
  };

  if (isLoading) return <Spinner />;
  if (!task) return <ErrorState type="notFound" />;

  return (
    <div className="task-card">
      <h3>{task.title}</h3>
      <button onClick={() => onComplete(taskId)} aria-label="Complete task">
        Complete
      </button>
    </div>
  );
};
```

## Hook Patterns

Custom hooks are critical to code reusability and maintainability. Follow these guidelines to ensure hooks remain focused, testable, and consistent.

### ✅ DO: Keep Hooks Focused (Single Responsibility)

**Max size: 150 lines per hook file**
**Max dependencies: 3 other custom hooks**

```typescript
// ✅ CORRECT - Focused hook with single responsibility
export function useTaskFilters() {
  const [filters, setFilters] = useState<TaskFilters>({
    status: 'all',
    priority: 'all',
    assignee: 'all',
  });

  const updateFilter = (key: keyof TaskFilters, value: string) => {
    setFilters(prev => ({ ...prev, [key]: value }));
  };

  const resetFilters = () => {
    setFilters({ status: 'all', priority: 'all', assignee: 'all' });
  };

  return { filters, updateFilter, resetFilters };
}
```

```typescript
// ❌ INCORRECT - Hook doing too much (500+ lines)
export function useTasksQuery() {
  // Query logic
  // Mutation logic
  // Business logic functions
  // Filter logic
  // Modal state
  // Form handlers
  // ... 500+ lines
}
```

### Migration Strategy

When splitting an existing large hook file:

1. **Identify Domains**
   ```bash
   # Find section markers to identify logical groups
   grep "^// ====" src/hooks/useFinanceQuery.ts
   ```

2. **Create New Files**
   - One file per domain
   - Keep related queries and mutations together
   - Maintain backward compatibility with barrel exports

3. **Update Barrel Export** (`index.ts`)
   ```typescript
   // src/finance/hooks/index.ts
   export * from './useAccountsQuery';
   export * from './useTransactionsQuery';
   export * from './useBudgetsQuery';
   // ... all domain hooks
   ```

4. **Gradual Migration**
   - Start with one domain at a time
   - Update imports incrementally
   - Test after each domain migration

5. **Maintain Compatibility**
   ```typescript
   // Old import (still works via barrel export)
   import { useAccounts } from '@/hooks/useFinanceQuery';

   // New import (preferred)
   import { useAccounts } from '@/finance/hooks/useAccountsQuery';

   // Also works (via barrel)
   import { useAccounts } from '@/finance/hooks';
   ```

## API Design

### Supabase API Patterns

```typescript
// ✅ CORRECT - Complete error handling
import { supabase } from '@/lib/supabase';
import { AuthenticationError, NotFoundError, DatabaseError } from '@/lib/errors';
import { logger } from '@/services/logger';

export async function updateTask(taskId: string, updates: Partial<Task>): Promise<Task> {
  // 1. Authentication check
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) {
    throw new AuthenticationError('Not authenticated');
  }

  // 2. Perform operation
  const { data, error } = await supabase
    .from('tasks')
    .update(updates)
    .eq('id', taskId)
    .select()
    .single();

  // 3. Handle errors
  if (error) {
    logger.error('API', 'Failed to update task', { taskId, error });
    throw new DatabaseError(error.message, { taskId, error });
  }

  // 4. Validate result
  if (!data) {
    throw new NotFoundError('Task', taskId);
  }

  // 5. Log success and return
  logger.debug('API', 'Task updated successfully', { taskId });
  return data;
}
```
