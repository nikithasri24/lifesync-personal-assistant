### Page Layout - Centered Content Container

All feature pages must use centered column layout:

```jsx
<div style={{ backgroundColor: colors.bg.primary, minHeight: '100vh' }}>
  <div style={{ maxWidth: '900px', margin: '0 auto', padding: '1.5rem', paddingBottom: '5rem' }}>
    {/* All page content */}
  </div>
</div>
```

**Key elements:**
- Outer container: Full-width with background color, `minHeight: '100vh'`
- Inner container: `maxWidth: '900px'`, `margin: '0 auto'` (centers content)
- Padding: `1.5rem` on all sides, `5rem` bottom for mobile nav
- Mobile: Uses full width minus padding
- Desktop: Content centered with max 900px width

### Page Header - Clean, No Duplication

```jsx
<h1 className="text-3xl font-bold flex items-center gap-3 mb-4" style={{ color: colors.text.primary }}>
  <span className="text-4xl">❤️</span>
  Together
</h1>
```

**Rules:**
- Single page header with feature emoji
- DO NOT duplicate tab name (already visible in bottom navigation)
- Use appropriate emoji for each feature
- `text-3xl font-bold` for title, `text-4xl` for emoji

### Modal Design Standards

All modals must follow this exact structure:

#### Modal Container
```jsx
<div
  className="fixed top-0 left-0 right-0 bottom-0 z-[60] flex items-end justify-center lg:items-center"
  style={{
    backgroundColor: 'rgba(0, 0, 0, 0.4)',
    backdropFilter: 'blur(4px)',
    marginTop: 'calc(-1 * env(safe-area-inset-top, 0px))',
    paddingTop: 'env(safe-area-inset-top, 0px)',
    height: 'calc(100vh + env(safe-area-inset-top, 0px) + env(safe-area-inset-bottom, 0px))',
  }}
  onClick={handleBackdropClick}
>
```

**Requirements:**
- Full-screen overlay: `rgba(0, 0, 0, 0.4)` + `blur(4px)`
- Mobile: `items-end` (slides from bottom)
- Desktop: `lg:items-center` (centered)
- Safe area insets: Handles mobile notches/home indicators
- z-index: `z-[60]` for proper layering

#### Modal Content
```jsx
<div
  className="w-full bg-white lg:rounded-3xl rounded-t-3xl overflow-hidden flex flex-col"
  style={{ maxHeight: '90vh', maxWidth: '600px' }}
>
```

**Requirements:**
- Shape: `lg:rounded-3xl` (desktop), `rounded-t-3xl` (mobile top only)
- Max width: `600px` (constrains on large screens)
- Max height: `90vh` (prevents overflow)
- Flex column: For fixed header/footer
- Background: White

#### Mobile Drag Handle
```jsx
<div className="lg:hidden pt-2 flex-shrink-0">
  <div className="w-9 h-1 rounded-full mx-auto bg-gray-300" />
</div>
```

**Requirements:**
- Only visible on mobile: `lg:hidden`
- Gray bar: `w-9 h-1 bg-gray-300 rounded-full`
- Centered: `mx-auto`
- Padding: `pt-2`

#### Modal Header (Fixed)
```jsx
<div className="flex items-center justify-between px-6 py-5 border-b border-gray-200 flex-shrink-0">
  <h2 className="text-2xl font-bold text-gray-900">Modal Title</h2>
  <button
    type="button"
    onClick={onClose}
    className="p-2 hover:bg-gray-100 rounded-lg transition-colors"
    aria-label="Close"
  >
    <X className="w-5 h-5 text-gray-500" />
  </button>
</div>
```

**Requirements:**
- Fixed: `flex-shrink-0` (doesn't scroll)
- Border: `border-b border-gray-200`
- Padding: `px-6 py-5`
- Title: `text-2xl font-bold text-gray-900`
- Close button: Hover effect, aria-label required

#### Scrollable Content Area
```jsx
<div
  className="overflow-y-auto p-6 space-y-5 flex-1"
  style={{ maxHeight: 'calc(90vh - 140px)' }}
>
  {/* Form fields */}
```

**Requirements:**
- Scrollable: `overflow-y-auto flex-1`
- Max height: `calc(90vh - 140px)` (accounts for header/footer)
- Padding: `p-6`
- Spacing: `space-y-5` between form fields

#### Modal Footer (Fixed)

```jsx
  <button
```

**Requirements:**
- Fixed: `flex-shrink-0` (doesn't scroll)
- White background: `bg-white` (prevents transparency)
- Border: `border-t border-gray-200`
- Padding: `px-6 py-4`
- Button layout: `flex gap-3`
- Cancel button: Gray `bg-gray-100 hover:bg-gray-200`
- Primary button: Terracotta gradient
- Loading states: Show loading text, disabled with opacity

#### Keyboard & Backdrop Support
```jsx
// ESC key closes modal
useEffect(() => {
  const handleKeyDown = (event: KeyboardEvent) => {
    if (event.key === 'Escape') {
      onClose();
    }
  };

  if (isOpen) {
    window.addEventListener('keydown', handleKeyDown);
    return () => window.removeEventListener('keydown', handleKeyDown);
  }
}, [isOpen, onClose]);

// Backdrop click closes modal
const handleBackdropClick = (e: React.MouseEvent) => {
  if (e.target === e.currentTarget) {
    onClose();
  }
};
```

**Requirements:**
- ESC key must close modal
- Clicking backdrop (outside modal) must close modal
- Modal content clicks should NOT close modal

### Auto-save Functionality

All forms with significant user input must auto-save drafts to localStorage:

```jsx
const STORAGE_KEY = 'feature_modal_draft';

// Load draft on mount
const loadDraft = () => {
  try {
    const saved = localStorage.getItem(STORAGE_KEY);
    if (saved) return JSON.parse(saved);
  } catch (error) {
    logger.error('Feature', error as Error, { context: 'Failed to load draft' });
  }
  return null;
};

const savedDraft = loadDraft();
const [field, setField] = useState(savedDraft?.field || '');

// Auto-save on every change
useEffect(() => {
  localStorage.setItem(STORAGE_KEY, JSON.stringify({ field, /* other fields */ }));
}, [field /* all form fields */]);

// Clear on success
const handleSubmit = () => {
  // ... submit logic
  localStorage.removeItem(STORAGE_KEY);
  onClose();
};
```

**Requirements:**
- Unique storage key per modal
- Load draft on component mount
- Save on every field change
- Clear after successful submit
- Handle JSON parse errors gracefully

## Logging

### ✅ DO: Use the Centralized Logger

**Always use the logger service instead of console.***

```typescript
// ✅ CORRECT
import { logger } from '@/services/logger';

logger.debug('MealPlanning', 'Fetching meal plans', { filters });
logger.info('Travel', 'User logged in successfully');
logger.warn('Finance', 'Rate limit approaching', { remaining: 10 });
logger.error('API', 'Failed to fetch data', error);
```

```typescript
// ❌ INCORRECT
console.log('Fetching meal plans', filters);
console.error('Failed to fetch data', error);
console.warn('Rate limit approaching');
```

### Logger Methods

- **`logger.debug(domain, message, context?)`** - Development-only logs for debugging
- **`logger.info(domain, message, context?)`** - Informational messages (dev only)
- **`logger.warn(domain, message, context?)`** - Warnings (dev + production)
- **`logger.error(domain, error, context?)`** - Errors (dev + production)
- **`logger.api(method, url, data?)`** - API request logging
- **`logger.apiResponse(method, url, status, data?)`** - API response logging

### Domain Names

Use consistent, descriptive domain names:
- **API Layer**: `'MealPlanning'`, `'Finance'`, `'Travel'`, `'Shopping'`
- **Services**: `'Service'`, `'Briefing'`, `'Nutrition'`
- **UI Components**: `'UI'`, `'Modal'`, `'Form'`
- **Hooks**: `'Hooks'`
- **Data Layer**: `'DataEvents'`, `'ReactQuery'`

### Context Objects

Always provide context for better debugging:

```typescript
// ✅ CORRECT
logger.error('API', 'Failed to update task', {
  taskId,
  userId,
  error: error.message,
  statusCode: error.statusCode
});
```

```typescript
// ❌ INCORRECT
logger.error('API', `Failed to update task ${taskId}`);
```

### Exceptions

Console usage is **only allowed** in:
- Test files (`*.test.ts`, `*.spec.ts`, `src/test/setup.ts`)
- Scripts (`src/scripts/**`)
- The logger service itself (`src/services/logger.ts`)

## Error Handling

### ✅ DO: Use Typed Error Classes

**Always use custom error classes from `@/lib/errors` instead of generic `Error`**

```typescript
// ✅ CORRECT
import { AuthenticationError, NotFoundError, AuthorizationError } from '@/lib/errors';

if (!user) {
  throw new AuthenticationError('Not authenticated');
}

if (!task) {
  throw new NotFoundError('Task', taskId);
}

if (!hasPermission) {
  throw new AuthorizationError('Access denied to shared resource');
}
```

```typescript
// ❌ INCORRECT
throw new Error('Not authenticated');
throw new Error('Task not found');
throw new Error('Access denied');
```

### Available Error Classes

| Error Class | Use Case | Example |
|-------------|----------|---------|
| `AuthenticationError` | User not logged in, invalid token | `throw new AuthenticationError('Not authenticated')` |
| `AuthorizationError` | Insufficient permissions, RLS violations | `throw new AuthorizationError('Access denied to project')` |
| `NotFoundError` | Resource doesn't exist | `throw new NotFoundError('Task', taskId)` |
| `ValidationError` | Invalid input data | `throw new ValidationError('Invalid email format')` |
| `NetworkError` | Connection issues | `throw new NetworkError('Failed to connect')` |
| `DatabaseError` | Database operation failures | `throw new DatabaseError('Query failed')` |
| `ServerError` | 5xx server errors | `throw new ServerError('Internal server error', 500)` |
| `ConflictError` | Duplicate entries, conflicts | `throw new ConflictError('Task already exists')` |
| `RateLimitError` | Too many requests | `throw new RateLimitError('Rate limit exceeded', 60)` |

### Error Handling in Try-Catch

```typescript
// ✅ CORRECT - Parse errors and use typed classes
import { parseToLifeSyncError } from '@/lib/errors';

try {
  await supabase.from('tasks').insert(task);
} catch (error) {
  const lifeSyncError = parseToLifeSyncError(error);
  logger.error('Tasks', lifeSyncError, {
    code: lifeSyncError.code,
    statusCode: lifeSyncError.statusCode,
  });
  throw lifeSyncError; // Re-throw the typed error
}
```

### React Query Error Handling

```typescript
// ✅ CORRECT - Use error helpers
import { getUserErrorMessage, isRetryableError } from '@/lib/errors';

const { error } = useQuery({
  queryKey: ['tasks'],
  queryFn: fetchTasks,
});

if (error) {
  const message = getUserErrorMessage(error); // User-friendly message
  return <ErrorState error={error} onRetry={isRetryableError(error) ? refetch : undefined} />;
}
```

## Accessibility

## API Design

### Supabase API Patterns

```typescript
// ✅ CORRECT - Complete error handling
import { supabase } from '@/lib/supabase';
import { AuthenticationError, NotFoundError, DatabaseError } from '@/lib/errors';
import { logger } from '@/services/logger';

export async function updateTask(taskId: string, updates: Partial<Task>): Promise<Task> {
  // 1. Authentication check
  const { data: { user } } = await supabase.auth.getUser();
  if (!user) {
    throw new AuthenticationError('Not authenticated');
  }

  // 2. Perform operation
  const { data, error } = await supabase
    .from('tasks')
    .update(updates)
    .eq('id', taskId)
    .select()
    .single();

  // 3. Handle errors
  if (error) {
    logger.error('API', 'Failed to update task', { taskId, error });
    throw new DatabaseError(error.message, { taskId, error });
  }

  // 4. Validate result
  if (!data) {
    throw new NotFoundError('Task', taskId);
  }

  // 5. Log success and return
  logger.debug('API', 'Task updated successfully', { taskId });
  return data;
}
```

2. Add the module name to the `ShareableModule` union type
3. Add a `MODULE_CONFIGS` entry for it
4. Only then use `getMergedConnectionId('your-module')` in your code

```typescript
// ❌ NEVER use a different module as a proxy
const connection = await getMergedConnectionId('goals'); // proxy for 'together' — BUG

// ✅ Add the real module to ShareableModule first, then use it
const connection = await getMergedConnectionId('together');
```

## Testing

### Test Structure

```typescript
// ✅ CORRECT - Comprehensive test
import { describe, it, expect, vi } from 'vitest';
import { renderHook, waitFor } from '@testing-library/react';
import { useTasks } from './useTasks';

describe('useTasks', () => {
  it('should fetch tasks successfully', async () => {
    const { result } = renderHook(() => useTasks());

    await waitFor(() => {
      expect(result.current.isSuccess).toBe(true);
    });

    expect(result.current.data).toHaveLength(3);
  });

  it('should handle errors properly', async () => {
    vi.mocked(fetchTasks).mockRejectedValue(new Error('Network error'));

    const { result } = renderHook(() => useTasks());

    await waitFor(() => {
      expect(result.current.isError).toBe(true);
    });

    expect(result.current.error).toBeDefined();
  });
});
```
