📱 Tab 2: Week - 7-Day Meal Grid

Mobile-optimized grid - meal types as columns, days as rows

✨ Why This Layout?

✅ Fixed Size Table: Consistent 72×88px cells
✅ Phone-Optimized: 373px total = fits iPhone perfectly!
✅ No Horizontal Scroll: Entire table visible on mobile
✅ Meal Patterns: Easy to spot "I eat oatmeal every Monday"
✅ Batch Cooking: See all dinners for meal prep planning
✅ Vertical Scroll: Natural mobile gesture (up/down)
✅ Predictable Layout: Same size cells = visual consistency
✅ Column Comparison: Compare breakfasts, lunches, etc.
✅ Today Highlight: Full row highlighted for current day
✅ Dense Information: Emoji + name + calories + time + portions

📐 Fixed Table Specifications

Cell Dimensions

Day Label Column: 45px wide
Meal Cell: 72px × 88px (fixed)
Cell Padding: 6px all sides
Border Spacing: 8px between cells
Border Radius: 10px
Border: 2px solid #E8DCC8

Content Sizing

Emoji: 18px (centered)
Meal Name: 9px, bold, 2-line max
Calorie Badge: 8px
Time Badge: 7px with ⏱️ icon
Portions: 7px, gray text
Status Dot: 6px circle (top-right)

Table Math

Meal Columns: 72px × 4 = 288px
Spacing: 8px × 5 gaps = 40px

🎯 Swapped Layout Benefits

✅ Advantages

• Mobile-First: Only 4 columns fit perfectly on phone
• No Horizontal Scroll: Everything visible without panning
• Pattern Recognition: Easy to see "I eat oatmeal every Monday"
• Meal Prep Planning: Great for batch cooking same meals
• Column Comparison: Compare all breakfasts at once
• Vertical Scrolling: Natural mobile gesture
• More Screen Real Estate: Wider cells for meal names

⚠️ Trade-offs

• Day View: Can't see all meals for one day at once
• Less Familiar: Not the traditional calendar pattern
• Vertical Length: 7 rows (one per day) to scroll
• Daily Planning: Harder to plan "what to eat today"
• Today Highlighting: Entire row vs entire column
• Date Labels: On left instead of top

💡 Use Case Scenarios

Choose Days Horizontal If:
You plan meals day-by-day
You want traditional calendar view
Desktop is primary device
Choose Meals Horizontal If:
Mobile is primary device
You batch cook same meals
You want pattern visibility

Delete Postpone

💻 Technical Implementation Notes

Key considerations for development

Component Architecture

Main Components

MealPlanning.tsx
├── MealPlanToolbar (week nav, actions)
├── WeeklyOverviewSection
│ ├── MealGridHeader (day labels)
│ ├── MealRow (per meal type)
│ │ └── MealCell (individual meals)
│ └── AddMealControl
├── NutritionSummary
│ └── NutritionCard (cal, protein, carbs)
├── SavedRecipesSection
│ ├── RecipeSearchBar
│ ├── FavoritesFilter
│ └── RecipeCard
├── ImportSections
│ ├── URLImport
│ ├── YouTubeImport
│ └── ManualEntry
└── Modals
├── GroceryListModal
├── RecipeFormModal
├── RecipeViewModal
├── CopyWeekModal
└── ImportRecipeModal

State Management

• React Query for recipes, meal plans, planned meals
• Local state for current week, modal visibility
• Multi-cell selection for bulk operations
• Grocery list state with localStorage persistence
• Recipe filtering (search, favorites)
• Week navigation with date calculations

Mobile Optimizations

• Horizontal scroll for 7-day grid on small screens
• Meal cells minimum 56px tap target
• Sticky headers (status bar, page header, week nav)
• Bottom sheet modals for mobile feel
• Haptic feedback on meal add/delete
• Pull-to-refresh for week data
• Lazy loading for recipe images
• Safe area insets for iPhone notch

Data Flow

1. User adds meal → Creates PlannedMeal record
2. Meal linked to Recipe (if exists) or custom meal
3. Nutrition auto-calculated from recipe data
4. Grocery list aggregates ingredients from all week's recipes
5. Duplicate ingredients merged with quantity sum
6. Real-time sync via Supabase subscriptions
7. Partner meals visible in merged mode
